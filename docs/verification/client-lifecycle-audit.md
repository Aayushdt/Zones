# Client Lifecycle Audit — 2026-10-20

| Audit claim | Finding | Evidence |
|---|---|---|
| Persisted Zustand state keeps match ID/session across a tab close | No. Zustand persists only theme, map style, haptics, and guest display name under `xzones.preferences`. The guest auth session is stored separately in `localStorage` under `xzones.guest_session`. No active match/player identity is persisted, so restoring the guest token alone does not rejoin a match. | `apps/web/src/stores/app-store.ts:7-30`; `apps/web/src/services/supabase-api.ts:59-103` |
| GPS `watchPosition` resumes after iOS backgrounding | Not guaranteed. The watcher is started once and cleared only on component teardown. `visibilitychange` syncs server state but does not reacquire GPS; there is no `pageshow` or watcher-error restart. Browser/iOS lifecycle behavior was not device-tested. | `apps/web/src/components/LocationSharing.tsx:37-39,78-96`; `apps/web/src/services/device-lifecycle.ts:7-18` |
| Screen Wake Lock support in Safari | The audit's blanket claim that Safari does not support it is stale. Apple lists Screen Wake Lock API support in Safari 16.4 release notes. WebKit later documented a Home Screen web app issue and a fix in Safari 18.4, so API availability alone does not establish reliability in older installed iOS PWAs. The app feature-detects `navigator.wakeLock`, requests while an active match is visible, releases while hidden, and retries on visibility restoration. | `apps/web/src/services/device-lifecycle.ts:35-67`; `apps/web/src/pages/MatchPage.tsx:87-91`; `tests/audit/client_logic_audit.test.ts:62-87`; [Apple Safari 16.4 release notes](https://developer.apple.com/documentation/safari-release-notes/safari-16_4-release-notes); [WebKit Safari 18.4 notes](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/) |

The Wake Lock lifecycle test passes, but no real iOS device or installed-PWA test was available. Reacquiring the geolocation watcher is explicitly left to Step 4.1; persisted match rejoin is left to Step 4.4.
